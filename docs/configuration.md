[返回项目首页](../README.md)

## 请求并发与会话继承

- 模型添加/连通性测试的无标识单轮请求可使用临时预约：必须只有新输入，不能带既有助手/工具/加密历史、父关系或响应引用；每次请求独立，仍受 Key 请求上限保护，完成后不保留会话绑定。适用于 Trae 等客户端的无会话测试形态，不通过伪造固定会话头绕过校验。
- 正式多轮请求仍需稳定 ID（支持显式会话头以及正文或正文 metadata 中的 session_id/thread_id）。单次 execution/request ID 不作为持久会话身份；冲突或非法 ID 不会降级为匿名探测。无标识且带历史的请求继续保守拒绝。
- 每个 API Key 只配置一个 `max_concurrent_requests` 请求并发上限，默认 **2**，范围 **1–100**。主代理、子代理、同会话多请求和其他会话共用该 Key 的执行名额；闲置会话不占名额。
- 升级时优先沿用已有 `max_concurrent_requests`，缺失时使用旧 `max_concurrent_sessions`，再缺失使用 2。旧会话数上限和 `max_concurrent_requests_per_session` 不再单独限流；通过界面保存后移除旧字段。
- 超出上限按预约顺序排队，不切换已绑定的 Key。排队最长沿用 `retry_budget_seconds`（默认 180 秒），超时返回 `ar_concurrency_wait_timeout` / 429；排队预算和之后的重试预算分别计算。正常生成不受等待预算截断。
- 完成、失败、客户端取消后释放名额；终止事件交付前先释放，重复清理安全。重试退避期间保留执行名额以抑制重试风暴。降低上限不打断已在途请求，新请求按新配置排队。
- 相同 Key 的重复凭证共享计数；有在途请求时按它们声明的较小请求上限执行，建议重复配置一致。多个独立 CPA 实例不共享全局配额。
- 新会话按同优先级 Key 的在途/排队请求数均衡分配，数量相同时轮流选择；继承和续聊不推进轮流分配游标。
- 显式父会话引用优先继承同调用方范围内父会话的 AR Key，允许携带父历史的新子会话接续。支持 CPA 解析的 `parent_session_id` 元数据、`X-Codex-Parent-Thread-Id` / `X-Parent-Session-Id` 等请求头、正文/metadata/extra_body 中的父 session/thread/fork 标识。不同引用冲突、自引用或非法 ID 会保守拒绝。
- Codex 的 Session/Thread 双 ID 和命名子代理保留独立子会话身份；子会话可以继续产生孙会话。已有子会话自身绑定优先，不被父关系覆盖。已绑定 Key 暂时不可用时等待原 Key 恢复，不改用其他 Key 或供应商。
- 父子关系只决定路由，不合并历史，不修改客户端的 `prompt_cache_key`。同 Key 有利于缓存复用，但上游资源调度、输入前缀和缓存规则仍决定实际命中。
- 对齐 CPA 8.0.61 的显式继承思路；插件调度器自行保证 AR 来源与固定 Key，不声称完全复用 CPA 的全部 LCP、跨模型 guardian 或失效重绑定行为。识别依据见 [CPA 会话解析源码](https://github.com/router-for-me/CLIProxyAPI/blob/v8.0.61/sdk/cliproxy/session/info.go) 与 [亲和选择器](https://github.com/router-for-me/CLIProxyAPI/blob/v8.0.61/sdk/cliproxy/auth/selector.go)。
- DSH 必须使用 `api: openai-responses`。通用适配器通过 `X-Client-Request-Id` 或 `prompt_cache_key` 传会话 ID；同时存在时要求一致。没有父引用时不会从相似提示词、时间或模型名猜测继承关系。需要 DSH 客户端传递父 ID 才能自动归属父 Key。
- 非 AR 来源会话及其子会话不会混入 AR；不认识的旧历史仍保守拒绝。首次升级缺少来源记录的旧会话需新建。CPA 明确标记 `history_initialization=new` 且没有历史的失败初始化仍可按原规则重试；`cold_resume` 不适用。

调度插件在候选含 AR 时处理选择；没有 AR 候选时，已绑定 AR 的会话明确拒绝，其他会话仍委托原调度。混合候选先保留可用的原会话亲和，再按最高可用优先级与权重选择供应商；选中 AR 后按 Key 均衡分配。已绑定 AR 的会话始终限定在原 Key。这部分由插件执行，因为当前宿主接口没有“移除部分候选后再交回原选择器”的接口。若部署了另一个调度插件，需要确认不会覆盖本插件；执行器还会二次验证名额，未获准不会请求 AR。

状态文件为 CPA 工作目录下 `plugins/cpa-agentrouter-continuity-sessions.json` 与 `.lock`。另有同目录 `.json.executions` 与 `.json.executions.lock` 保存请求排队/执行名额，以兼容旧共享库在途热更新。只有会话哈希、来源、凭证标识、Key 哈希和名额，没有聊天正文或密钥。权限 600；热更新与重启保留来源，重启清除旧进程名额。迁移时可私下迁移此状态文件；缺失时已有历史会话不会被视为新会话。不要在服务运行时删除状态或锁文件。若状态不可读/损坏，保守关闭 AR 准入，其他可用候选仍可用。

限制在同一 CPA 工作目录内有效；多个独立 CPA 实例并不共享全局并发配额。当前文件锁实现支持 Linux、macOS、FreeBSD 和 Windows；其他平台需要补充相应的跨进程锁实现，不能直接宣称支持。

## 管理页面

客户端错误使用 `channel_` 前缀，例如 `channel_session_ineligible`、`channel_upstream_timeout`。错误后缀、HTTP 状态和追踪编号用于排查；管理监控中的内部错误码保留原有前缀，两者后缀对应。具体重试和调度判断仍基于内部错误分类。

从 CPA 的插件菜单打开 **AR Continuity**：

1. 输入 CPA **管理密钥**，点击「连接」或按回车。
2. 可勾选「记住密钥」，下次自动连接。也兼容 CPAMC / CPAMP 已记住的管理密钥。
3. 页面配色跟随管理面板的明暗主题；单独打开时跟随浏览器系统主题。

管理密钥与 AR API Key 是两个用途不同的密钥。记住管理密钥会将其保存在当前浏览器、当前站点的本地存储中；「断开连接」清除本插件保存的副本，不改变主面板自己的记住设置。AR API Key 不保存在浏览器本地存储中，不回显完整值。

### 仪表盘

首页采用 CPAMP 的浅蓝灰色系、细边框卡片与紧凑仪表盘布局，并跟随宿主明暗主题。

- **监控状态**：采用 CPAMP 风格的扁平分段条，每个 Key 显示最近 20 个 10 分钟时段（含当前时段）。按完成 ÷（完成 + 失败 + 未完整）在红、黄、绿之间渐变，无已结束请求显示灰色；取消和进行中请求不计入完成率，内部重试后成功仍计为完成。悬停或方向键聚焦可查看时段与计数。状态文字按 ≥90%、≥50%、<50% 分为正常、需关注、异常。
- **今日概况**：按北京时间汇总请求、完成率、Token 用量、内部恢复、最近 30 分钟请求速率和平均首段延迟。完成率不包含取消请求；首段延迟仅统计已记录首段的流式请求。
- **流量与时间线**：请求 / Token 趋势支持近 1 小时、近 6 小时与今日切换；今日时间线按 10 分钟显示，尚未到达的时段单独标记。
- **模型成本排行**：可按请求量、Token 或估算费用排序。点击「设置单价」填写每百万 Token 的普通输入、缓存命中和输出单价；内置渠道默认值，「获取渠道定价」读取 AgentRouter 公开接口并填入表单，保存后生效。手动单价优先；取消、获取失败或过期异步结果不覆盖原值。只保存在当前浏览器，不改变上游计费。普通输入扣除缓存命中，输出已包含推理 Token。三项全部留空表示未配置，填写 0 表示免费。
- **统计边界**：5 分钟聚合保留最近 24 小时，不受 200 条日志上限影响，但仅覆盖本次插件运行；进程重启或换版后重新计数。请求按开始时间归属，结果与 Token 在结束后入账；当前时间桶仍在累计。升级前的请求不回填。
- **用量与费用边界**：仅汇总上游最终响应明确返回的数值用量。缺失用量显示「—」，未配置单价不算作零费用；失败尝试、额外收费和阶梯规则未纳入，估算不代表实际账单。加载旧服务数据时会标明仅覆盖最近 200 条记录。

### 渠道单价

默认值核实于 **2026-11-06**，来自 `https://agentrouter.org/api/pricing` 的 `default` 分组，并与官网页面的换算核对：输入 = `model_ratio × 2 × group_ratio`，输出再乘 `completion_ratio`，单位为 USD / 百万 Token。

| 模型 | 普通输入 | 缓存估算 | 输出 |
| --- | ---: | ---: | ---: |
| gpt-5.6-sol | 4 | 4 | 20 |
| gpt-6.1-sol | 4 | 4 | 20 |
| gpt-6-astra | 10 | 10 | 50 |

公开接口当前**未公布缓存价**，缓存暂按普通输入价估算，表单标明该假设；若后续接口返回 `cache_ratio`，获取时采用该倍率。未知模型不猜价，账号专属折扣与阶梯计费不纳入；按次计费或带阶梯表达式的模型跳过。自动匹配已配置模型的上游名称和前缀；映射冲突时不套用默认值。清空三项并保存可取消该模型估算，0 表示免费。

获取通过已鉴权的插件 `GET /pricing` 接口，由 CPA 访问固定的公开 URL，沿用宿主网络；不发送 CPA 管理密钥、AR API Key 或账号 Cookie 给定价站点，不自动轮询。

### API Key 管理

支持新增、编辑、启用和停用。每个 Key 独立配置名称、模型与别名、可选前缀、请求并发上限、请求头、重试次数和预算。上限保存后用于后续请求，调低不会中断已在途请求；超限请求排队。编辑时 Key 留空表示保留；新增时必须输入 Key。

模型输入框旁的「获取模型」会直接读取 AR `/v1/models`。编辑现有凭证且 Key 留空时使用已保存 Key；新增或填写新 Key 时使用表单中的值，不会提前保存。弹窗支持搜索、多选、全选/清空当前搜索结果；输入框已有模型默认勾选，别名保留。本次未返回的已有模型也保留为可选项，避免静默删除。确认只填入表单，保存配置后才生效；取消或获取失败不会改动原模型列表。

不需要账号登录或 OAuth 授权。插件沿用 CPA 的凭证存储、文件权限和热加载机制；只允许修改本插件的 AR 凭证。页面不显示其他供应商凭证。

### 请求日志与健康

每 5 秒刷新，支持请求 ID / 模型 / 错误码搜索、状态和 Key 组合筛选、20 / 50 / 100 条分页及请求详情。展示进行中的请求及最近 200 条结束记录：模型、凭证名称、状态、尝试次数、首段延迟、总耗时、重试原因和错误码。不记录对话正文、工具参数或完整密钥。日志和健康检测结果保存在内存中，进程重启或插件换版后重新开始；不导入旧版本的请求历史。

连接页分开展示每个 Key 的近期完成率、手动检测结果与当前配置；可直接打开该 Key 的策略编辑。手动「检测连接」访问 AR 的模型列表接口，不发送生成请求；列表成功不能保证实际模型生成成功。检测沿用 CPA 全局代理。不会自动定时调用 AR。

## 默认请求头与密钥

内置默认值：

```text
User-Agent: codex_exec/0.159.3 (Windows 10.0.19045; x86_64) dumb (codex_exec; 0.159.3)
Originator: codex_exec
```

请求头未填写或为空时自动使用上述默认值，可覆盖为其他 AR 接受的 Codex/Zcode 客户端标识。认证头始终从当前凭证的 `api_key` 构造，不能被自定义请求头替换。

默认 User-Agent 是上游兼容标识，在 Linux 上同样使用，不用于判断宿主操作系统。AR 请求中的 `collaboration` 工具命名空间会转换为 `cpa_ar_collaboration`，返回时恢复；只转换协议工具标识，不改参数、结果正文或加密历史。客户端已占用相同别名时明确报错。

**源码、示例与二进制不包含可用 API Key 或管理密钥。** 示例 `api_key` 为空。运行时凭证必须由使用者填写或从原机器私下迁移，禁止加入源码和分发包。

## 迁移到另一台机器

分发的 `.so` 适用于 **Linux amd64 / x86-64、glibc 2.28 或更新**；`.dll` 适用于 **Windows amd64 / x86-64**。本轮 Linux 隔离验证使用 CPA **8.0.34（插件 RPC schema 6）**。其他版本需要兼容同一插件 ABI、管理与流式回调接口；仅看版本号更大不能保证兼容。ARM、macOS 和 musl/Alpine 需要对应平台重新编译。

1. 备份目标机配置。确认服务账号、工作目录、`plugins.dir` 和 `oauth.auth-dir`。
2. 将 `cpa-agentrouter-continuity-v0.5.2.so` 放入 `<plugins.dir>/linux/amd64/`。目录与文件必须由 CPA 服务账号可读；权限通常为目录 755、插件 644。
3. 在 CPA 插件管理中启用 **cpa-agentrouter-continuity**，完成热加载。无需为了安装插件修改现有供应商配置。
4. 打开插件页面，输入目标机 CPA 管理密钥，新增 AR API Key；或私下复制已有 AR 凭证到目标机认证目录。凭证应由服务账号拥有、权限 600。不要把认证目录打进公开安装包。
5. 核对目标机代理和域名分流。插件使用宿主全局代理，**不会自动复制原机器的 mihomo 配置，也不会自动保证非 ISP 出口**。若需要普通节点出口，须在目标机为 `agentrouter.org` 单独设置规则。
6. 用可选的临时模型前缀验证路由。确认正常后，自行决定是否保留前缀。没有前缀的模型可能参与同名模型的调度。

Windows 使用同一套配置步骤，将 `cpa-agentrouter-continuity-v0.5.2.dll` 放入 `<plugins.dir>/windows/amd64/`。Windows 版本使用系统 `LockFileEx` 保护会话状态，并以进程创建时间区分 PID 重用。

旧的 AR API 提供商条目可以在插件凭证已完整配置并验证后删除。不要同时启用旧条目和新插件凭证，否则旧条目仍可绕过插件。插件凭证独立保存 Key、模型和请求头，删除旧条目不会删除插件凭证。

### 可选文件方式

`../examples/cpa-agentrouter-continuity.example.json` 提供不含密钥的模板。可在源码目录以外安全生成一个默认停用的运行时凭证：

```sh
python3 scripts/create_credential.py --output /secure/runtime/cpa-agentrouter-continuity.json
```

命令在终端隐藏输入 API Key，不接收命令行明文 Key。之后设置正确的服务账号属主，再导入 CPA。启用前核对模型和前缀。

`model_prefix` 默认空；填写 `ar` 时只发布 `ar/模型名`，不额外发布对应裸模型。不要同时叠加宿主通用 `prefix` 字段。`models[].ID` 是基础显示名称，`Name` 为上游模型名。

## 恢复规则与边界

- 默认额外重试 4 次，允许 0–10；等待预算默认 180 秒，最多 600 秒。
- 临时限流使用 10/20/40/60 秒退避；网关或早期断流使用 1/2/4/8/15 秒退避，并添加少量抖动。
- 尊重 Retry-After 及毫秒形式。预算限制后续重试，不中断已在正常生成中的响应。
- 已交付内容、工具事件或未知可能带副作用的事件后，不再自动重放。
- 上游 `no_capacity`（HTTP 或 SSE）在尚未输出时按 5/10/20/40/60 秒退避，受原 Key 的次数和等待预算限制，遵守更长的 Retry-After；保留原历史和模型，耗尽返回 `no_capacity` / 503。输出后禁止重放。
- 已准入 AR 的会话在尚未交付内容时，加密 reasoning 校验失败及跨资源错误最多内部额外重试 2 次，约 1/3 秒退避；计入该 Key 现有总次数和等待预算，设置为 0 则不重试。原 Key、模型和完整历史保持不变。
- 内部重试沿用同一前台连接，成功时只交付正常结果，耗尽预算后才返回一次最终错误；已交付文字、推理或工具事件后不重放。外部客户端再次发起新请求时会重新计算本次请求预算，因此内外层重试仍可能叠加。
- 历史校验持续失败时返回 `ar_history_verification_failed`，保留原始原因及 trace_id，提示稍后重试或持续失败后再考虑新建会话。上游连接失败等情况提供 HTTP 状态与可用的底层原因。
- 认证失败、余额/配额耗尽、普通参数错误不重试。
- 上游计费规则编译异常（`tiered expr run failed` 同时包含 `expr compile error`）返回 `ar_upstream_pricing_error`，即使上游包装为 HTTP 500 或 SSE 错误也不自动重试；已输出文本保留，及时释放名额。提示中保留未知变量名和 `trace_id`，便于上游维护者排查；客户端仍可自行发起新请求。
- `response.incomplete` 的原因为 `content_filter` 时，流式返回一次 `ar_content_filter` 终止错误（插件发出 `response.failed`，宿主可转换为 `error` 事件），非流式返回 HTTP 400；已输出文本保留，插件不重放请求。`max_output_tokens` 等其他未完成原因继续透传。该规则不能阻止客户端自行发送新请求，也不会解除上游内容过滤。
- 插件凭证的 CPA 外层 `request_retry` 为 0，避免与插件自身的重试轮次叠加；其他凭证不受影响。
- 首版完整验证范围是 HTTP/SSE。没有验证 WebSocket；压缩端点保守透传，未测试真实上游压缩任务。

这是故障恢复层，不是任意流中断后的无损断点续传。请求重试仍可能增加上游用量。

## 更新与回滚

使用新版本文件名放入插件目录，然后通过 CPA 插件管理保存配置触发热加载。不要直接覆盖正在使用的动态库；保留旧文件用于回滚。热加载机制依赖宿主版本，先在隔离实例验证。

旧版本回滚时移走新版本文件，再通过管理面板重新加载旧版本。只改本插件配置，不覆盖整份历史 CPA 配置，不重启其他服务。停用插件前先停用对应 AR 凭证，避免无执行器路由。

第三方版权和许可原文集中保存在 `../licenses/`、`../internal/sdk/LICENSE` 和 `../THIRD_PARTY_NOTICES.md`，不作为界面或产品文档的参考链接展示。

## 从旧插件迁移

本次统一更改了项目名、Go module、插件/provider 标识、管理接口路径、浏览器存储名称及状态文件名。这是一次标识不兼容的更新，不是把新文件直接放在旧插件旁即可替换。

现有运行实例不会被仓库发布自动修改。迁移前备份凭证和会话状态，等待旧插件没有在途请求后再切换；不要让旧、新两个调度插件同时启用。

1. 在隔离实例先验证新包，再停用旧插件的 AR 凭证与旧插件。
2. 将私有凭证的 `type` 改为 `cpa-agentrouter-continuity`，模型 `OwnedBy` 改为相同值；保留原 `id`、API Key、名称、优先级、权重、模型前缀与其他配置。新凭证文件使用新项目前缀，避免重复导入。
3. 如要保留会话来源，将旧来源状态文件复制为 `plugins/cpa-agentrouter-continuity-sessions.json`；将 `origins` 中旧 AR provider 值转换为 `cpa-agentrouter-continuity`，保持非 AR provider 与会话哈希不变。只在确认无在途请求后清空 `leases`，不要删除旧备份。文件由 CPA 服务账号拥有，权限 600。
4. 安装新动态库，在 `plugins.configs.cpa-agentrouter-continuity` 启用它，再按需启用迁移后的凭证。旧库留在插件目录外作为回滚备份。
5. 新管理页面可复用主面板记住的管理密钥；旧插件自身的浏览器记住记录不会自动迁移。确认模型目录、状态与出口正确后再使用。

如果没有迁移会话来源，已有带历史的会话会保守绕开 AR，新建会话可按准入规则使用。迁移材料含私有密钥时必须单独安全传输，不能提交到仓库或上传 Release。
